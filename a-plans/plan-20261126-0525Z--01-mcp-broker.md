# OM MCP — initial implementation plan

Timestamp: 2026-11-26 05:25 UTC (Zulu)
Status: Proposed — implementation pending explicit approval.

## Objective
Build a standalone Apache-2.0 MCP broker connecting external AI clients to Open Modeling browser sessions. All calculations remain in the browser. Cloudcell makes no LLM calls, charges no AI credits, and targets zero infrastructure spend.

## Scope and architecture
- Public endpoint proposed: https://mcp.cloudcell.nz/mcp; browser application remains https://om.cloudcell.nz/.
- Remote MCP over Streamable HTTP; browser-side authenticated WebSocket; isolated session routing (evaluate Cloudflare Workers and Durable Objects).
- Provider-neutral protocol supporting compatible ChatGPT, OpenCode, Hermes and other MCP clients; self-hosting supported.
- Reuse existing OM command/query contracts after read-only inspection of om-tools and om-tools-web; do not copy engine code.
- No persistent financial payload storage, no payload logging, no arbitrary code execution.

## Execution plan
1. Inspect existing repositories, command schemas, license ownership and established plan conventions. Verify current MCP specification, Cloudflare free limits and ChatGPT public plugin eligibility, including Free-plan write access. Record findings in docs/.
2. Specify typed command allowlist, request/response correlation, bounded payloads, timeouts, cancellation, reconnect and replay handling.
3. Design explicit opt-in pairing, short-lived single-use pairing codes, authenticated per-model scopes, OAuth-compatible MCP authorization, revocation and browser-side independent validation. Threat-model cross-session access, malicious brokers, prompt injection, origin abuse and resource exhaustion. Require local confirmation for destructive operations and sensitive exports; do not claim broker blindness without end-to-end protection.
4. Build minimal TypeScript proof of concept using compatible MCP SDK: pair one browser session, create one cube, read one calculated value. No changes to existing repositories without separate approval.
5. Add automated protocol, authorization, isolation, replay, disconnect, rate-limit, malformed-input and resource-bound tests. Verify no sensitive payloads appear in logs.
6. Benchmark CPU and request consumption on free infrastructure; enforce application quotas, fail closed on exhaustion, do not enable paid plans or deploy without approval. Provide local/self-hosted deployment instructions.
7. Validate with representative MCP clients. Prepare ChatGPT directory submission only after verifying requirements, consent, privacy and security review.

## Acceptance gates
- Unpaired or unauthorized clients cannot read or mutate models; sessions cannot cross.
- Browser independently enforces command permissions and can revoke access immediately.
- No arbitrary execution, unrestricted file access or persistent financial payload storage.
- No Cloudcell LLM expenditure; free-tier limits respected with service denial rather than paid escalation.
- Successful end-to-end cube creation and result retrieval; documented unresolved limitations.
- Independent security review before public launch.

## Deliverables
Architecture, security/threat model, deployment documentation, minimal broker, automated tests, compatibility matrix and release checklist.

## Open decisions
Exact tool schema, identity provider, pairing protocol, Cloudflare runtime compatibility and limits, public ChatGPT Free-plan entitlement, and whether stronger end-to-end authentication is needed for the broker trust model. No implementation or deployment authorized by this plan alone.
